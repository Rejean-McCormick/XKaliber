# Flux UX principaux

## Flux 1 — Passer une épreuve

```text
Accueil
→ Choix du domaine
→ Consentement
→ Scan initial
→ Épreuve adaptative
→ Résumé provisoire
→ Profil de Calibre
→ Options : sauvegarder, partager, contester, recalibrer
```

## Flux 2 — Créer une épreuve

```text
Créer un domaine
→ Définir les compétences
→ Définir les niveaux
→ Ajouter des items
→ Définir les critères
→ Tester l’épreuve
→ Soumettre à validation
→ Publier
```

## Flux 3 — Générer une CertifiKation

```text
Profil de Calibre
→ Vérifier seuil de certification
→ Générer Sceau CertifiKation
→ Ajouter au portfolio KonnectED
→ Définir partage public/privé
→ Planifier recalibrage
```

## Flux 4 — Réviser un résultat

```text
Profil contesté
→ Motif de contestation
→ Revue des traces
→ Intervention humaine
→ Décision de maintien/correction/reprise
→ Journal d’audit mis à jour
```

## Flux 5 — Alimenter EkoH via K-Port

```text
Profil de Calibre / Sceau CertifiKation
→ Consentement
→ Paquet d’évidence borné par domaine
→ Handoff vers K-Port
→ Contrôle de provenance, statut, portée, identité et consentement
→ Mapping / admissibilité K-Port
→ Signal transmis par K-Port à EkoH
→ EkoH décide de l’impact réputationnel
→ Affichage explicable dans le profil Konnaxion
```

Une contestation du **résultat d’évaluation** retourne vers XKaliber. Une contestation de **l’admissibilité ou du mapping de l’évidence** relève de K-Port. Une contestation du **score de réputation** relève d’EkoH.
