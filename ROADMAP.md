# Roadmap — XKaliber

## Phase 0 — Cadrage

- Définir le langage produit.
- Définir les domaines de compétence initiaux.
- Définir les niveaux de difficulté.
- Définir les types d’épreuves.
- Définir les sorties attendues.
- Rédiger les principes de gouvernance.

## Phase 1 — Prototype conceptuel

Objectif : simuler une évaluation sans choix technique final.

Livrables :

- modèle de compétence ;
- banque d’items fictifs ;
- règles d’adaptation ;
- exemples de sessions ;
- exemples de profils ;
- grille de lecture pour évaluateurs.

## Phase 2 — MVP fonctionnel

Objectif : faire passer une épreuve adaptative simple.

Fonctions :

- création d’un domaine ;
- création de compétences ;
- création d’items ou tâches ;
- lancement d’une session ;
- ajustement de difficulté ;
- génération d’un Profil de Calibre ;
- export d’un Sceau CertifiKation.

## Phase 3 — Validation organisationnelle

Objectif : rendre le système utilisable par une école, équipe ou organisation.

Fonctions :

- espace évaluateur ;
- tableaux de bord ;
- comparaison de cohortes ;
- suivi de progression ;
- commentaires humains ;
- audit de l’évaluation ;
- mécanisme de contestation.

## Phase 4 — Intégration Konnaxion

Objectif : connecter XKaliber au cycle plus large.

Fonctions :

- portfolio KonnectED ;
- preuve CertifiKation ;
- signal de domaine vers EkoH ;
- usage possible dans SmartVote ;
- intégration à des parcours d’apprentissage ;
- historique de recalibrage.

## Phase 5 — Gouvernance avancée

Objectif : rendre les règles révisables et publiques.

Fonctions :

- versionnement des règles ;
- comités de validation ;
- tables de validation ;
- analyse d’équité ;
- rapports de biais ;
- processus d’appel ;
- seuils publics par domaine.
